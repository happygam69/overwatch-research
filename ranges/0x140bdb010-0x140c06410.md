# Pass 68 — chunks `0612`–`0619`, `.text` `0x140bdb010`–`0x140c06410`

Pass 67 stopped exactly on a chunk boundary inside the `AuthenticationSystem` tower, so
the pass-67 watch list named `FUN_140bdd670`/`FUN_140bdd2d0` and the nine auth jobs as
the opening items. They are there — chunk 0612 finishes the auth *job* half (device
code, delegation poll, legal submit) and then the range leaves the tower entirely.
Three strata follow, and one of them is a wholly-new subsystem:

1. **`0x140bdb010`–`0x140be0a40`, the auth job callbacks + the ping/latency tracker.**
   The nine job bodies the pass-67 watch named, then the *client-side* network quality
   tracker (0xe0-B per-connection rows with a 0x28-sample ring and the
   `0xABC00CBA` ping message).
2. **`0x140be0c80`–`0x140bf3cb0`, masked-pointer containers + the class/definition
   registry over `0x142d3bxxx`.** Generic container machinery (masked-pointer list,
   0x90-row merge sort, string-keyed sorted vector) and the RTTI-tag class graph whose
   predicate `FUN_140bf3cb0` decodes ~25 `DAT_14412xxxx` tag objects.
3. **`0x140bf4160`–`0x140c06410`, a JSON-Schema validator + template instantiator.**
   This is the pass's find. `0x1430a3798`–`0x1430a3958` is a plaintext JSON-Schema
   keyword table (`exclusiveMaximum`, `minLength`, `pattern`, `uniqueItems`,
   `additionalProperties`, `dependencies`, `required`, `oneOf`, `anyOf`, `enum`,
   `type`, `default`, `items`, …) and the band around it is a schema **compiler**
   (`FUN_140bf9610`, 30,014-B text: RPN token stream → 12-byte opcode program),
   **instantiator** (`FUN_140bfbdd0`, 60,322-B text, the range max) and **validator**
   (`FUN_140c01700`/`1900`, numeric min/max/step/modulus; `FUN_140c03340`/`3d70`,
   array FNV-1a folding). The diagnostics carry their own key names:
   `errors`, `expected`, `actual`, `missing`, `disallowed`, `duplicates`,
   `instanceRef`, `schemaRef`.

Zero registrations, zero records: **68 consecutive consumer-only passes**. 527
functions for 1,024,804 B of post-strip text.

## Zone 2 — the ping/latency tracker (`0x140bdf570`–`0x140be0c80`, then 0613's tail)

The clearest new mechanism in chunk 0612's second half.

- Row layout (0xe0 B): `+0x00` u8 active, `+0x04` int connection id, `+0x08` string
  name, `+0x28` float accumulated, `+0x2c` **float[0x28]** sample ring, `+0xcc` int
  ring index, `+0xd0` wrapped flag, `+0xd4` int sample count, `+0xd8` int reply count,
  `+0xdc` float timeout. The ring length 0x28 is a hard constant in
  `FUN_140be0a40` (`if (*(int *)(lVar6 + 0xcc) == 0x28) { idx = 0; wrapped = 1; }`).
- `FUN_140be0a40` is the **ping reply consumer**. Guard: `*(byte*)(record+0xc) & 0xf == 1`
  and body length `== 0x20`; then `func_0x000142388770(body+0x22, 0x20)` and a u32
  read that must equal **`0xABC00CBA`** (`-0x543ff346` sign-extended). Body is
  `{u32 magic 0xabc00cba, u64 t0, u64 t1, u64 t2}`; the latency is
  `(t0 - t1) - |t2 - t1|` clamped at 0, `>>20`-scaled by `_DAT_142f7aadc`, then
  pushed into the ring with a running sum.
- `FUN_140bdfd50` drives it: `func_0x000141bb0d70()` (cvar) →
  `FUN_141bc08c0(setting, page, 0, 0)` gate → `FUN_142364de0(metric, !enabled)`,
  then an intrusive-list drain from `func_0x000142365130` with object kinds 1, 2, 4, 5
  (1 = added, 2/4 = removed, 5 = sample). Allocator/pool is the
  `FUN_142364xxx`/`FUN_142365xxx` metric subsystem — `FUN_142364f40` registers a named
  counter, `FUN_142364fe0` a named gauge.
- `FUN_140bdfaa0` + `FUN_140be06c0` are the **registration** half: the 0xa8-B
  descriptor rows at `param_2+0x80` (fields `+0x00` u64, `+0x08` u64, `+0x10` u32,
  `+0x14` u16, `+0x16` `char[0x20]`, `+0x36` `char[0x20]`, `+0x58` and `+0x80`
  strings) are walked and turned into metric registrations via
  `FUN_14237fa90`/`FUN_14237f5f0`/`func_0x000142380170`.
- The metric message serializer is `FUN_1423887b0`/`1423892b0`/`1423893d0`/`142388a00`/
  `func_0x000142388c60`/`142389a20`/`1423887e0`; `FUN_1423892b0(ctx, 0xabc00cba)` is
  the same message id in the **send** direction. `0x3e800000` (1000.0f) is the

## Zone 4 — JSON-Schema validator + instantiator (`0x140bf7c10`–`0x140c06410`, 110 fns)

The subsystem the pass exists for. Structure first, then the tables.

**The value/variant type** (`FUN_140bf7c10` = deep copy, the 25× most-called function
in the range). 16 bytes: `{u32 count @+0x00, u64 payload @+0x08 (48 bits used),
u16 tag @+0x0e}`. `tag & 7` selects:

| `tag&7` | meaning | payload |
|---|---|---|
| 0 | null / empty | — |
| 1 | bool false | — |
| 2 | bool true | — |
| 3 | array of 0x20-B elements | `payload` = base, `count` = n |
| 4 | array of 0x10-B elements | `payload` = base, `count` = n |
| 5 | string / binary | `tag` bit 0xc = inline SSO (len at `+0xd`), else `payload`+`count` |
| 6 | number | 8-byte inline, bit 9 = double, `0x20`/`0x40` = int/uint, bit 7 = signed |

Bits above 7 are flags: `0x100` = integral, `0x400` = present, `0x1000` = inline,
`0x2000`/`0x4000`… per arm. `FUN_140bf7e00` (ordered) and `FUN_140bf7fb0` (unordered
memcmp-of-keys) are the two equality predicates. `FUN_140bfe900` is the recursive
free (44 callers, the #1 call target of the whole range at ×81).

**The schema compiler**, `FUN_140bf9610` (30,014-B text, size=3688, 2 callers). It
reads a little token stream through the **LEB128/UTF-8 decoder `FUN_140bf8b50`** (950 B,
8 callers) whose class table is **`0x1430a3980`** (128 bytes; dumps all-zero in the
file image, so it is runtime-initialised like the pass-66 Newton blocks — T68-2) and
emits a **12-byte instruction** `{u32 a, u32 b, u32 c}` into the array at
`param_1+0x50`. Opcode/terminator bytes seen: `'$'` 0x24, `'('` 0x28, `')'` 0x29,
`'*'` 0x2a, `'+'` 0x2b, `'.'` 0x2e, `'?'` 0x3f, `'['` 0x5b, `'\'` 0x5c, `'^'` 0x5e,
`'{'` 0x7b, `'|'` 0x7c, `'}'` 0x7d, `'`'` 0x60 (`b`→8, `f`→0xc, `n`→10, `r`→0xd,
`t`→9, `v`→0xb after `\`), and `0x2d` `'-'` as the range separator. The node table is
`param_1+0x20` (0x10-stride `{u32 a, u32 b}`, `0xffffffff` = leaf), the index counter

`\…`-headed sub-expression and `FUN_140bfab70` scans digits; `FUN_140bfac00` is the
`param_3`/`param_4` two-mode reachability walk.

**The validator arms.** `FUN_140c01700` and `FUN_140c01900` are a **matched pair** on

(integer division + `movmskpd` round-down correction). `FUN_140c03340` and
`FUN_140c03d70` fold arrays into **FNV-1a 64** (`*0x100000001b3`) with fixed seeds
`0x400000006cc` (array), `0x30000000519` (array-of-pairs), and the pair element
`FUN_140c01430` seeds `0x84222325cbf29ce4` for booleans — the same
