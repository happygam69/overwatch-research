## What this range is

**Engine/UI runtime, not the registry machine** (evidence: `registrations: 0`, `records: 0`,
no `cd360`/`d4f30`/`d4f70`/`d4fb0`/`c2d50`/`c2d70`/`c7880` in 401 files; the only `atexit`
is the settings-id static above). The range is the client's **per-frame UI/gameplay layer**
built on the container/hash/handle library that pass 28 catalogued:

1. per-object updates and teardown of the app object and of scene ("world") objects,
2. a tracked-entity record system with priorities, flags, expiry timestamps and percentages,
3. the **hotfix/patch downloader** (HTTP create/send/poll, SHA-256 check, retry backoff),
4. a **parallel per-entity update** (up to 64 chunks) with a 3-way entity-type dispatch,
5. the **HUD layer**: world→screen projection, occlusion tests, quad records, icon/text draw,
6. an **event bridge**: `0xa4…`/`0x2400…`/`0xde0…`/`0xd8…` 64-bit event tags with typed
   payload writers, funnelled through the app vtable `+0x140`/`+0x150`,
7. **console-variable registration at scale** (3–4 duplicated blocks, ~50 vars each),
8. table/debug UI (column names in plaintext) and Battle.net "BGS" club plumbing.
